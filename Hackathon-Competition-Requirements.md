**07**Scoring

## Build for what the judges can verify.

A polished pitch cannot compensate for weak financial-inclusion value, decorative AI, or a BMONI integration that does not work.

**100**POINT SYSTEM

Each eligible project should be scored by at least two reviewers.

Reviewers and judges must declare conflicts of interest.

Ties: financial-inclusion impact → prototype quality → BMONI API integration.

01

### User problem + financial-inclusion value

Does the entry understand a specific user and create meaningful financial-inclusion value?

**20%**

### BMONI API integration

**15%**

03

### Useful + responsible AI

**15%**

04

Can reviewers test the central experience and verify the technical implementation?

**20%**

**15%**

**10%**

**08**Field manual

## Make the work legible. Make the claims honest.

01

### Build the judged work here

Pre-existing ideas and general-purpose code may be used when declared, but the judged solution and BMONI integration must be built during the official build period.

02

### Make AI useful

The AI component must create clear user value and be explained well enough for reviewers to understand its role.

03

### Make BMONI functional

Demonstrate a meaningful sandbox integration and explain the relevant endpoints and data flow.

04

### Use test data only

Never use live funds or real personal financial data during the hackathon.

05

### Protect people

Demonstrate responsible data, privacy, security, accessibility, and financial-safety practices.

06

### Declare every dependency

Name AI models, code, datasets, APIs, open-source tools, and pre-existing assets. Plagiarism, unsafe data use, or false claims may disqualify an entry.

07

### Compete independently

Enter individually or in a self-formed team of two or three. NITHUB will not match entrants into teams.

08

### Keep the prizes fair

Existing commercial products are not eligible for the main prizes; organizers, reviewers, judges, and event staff cannot compete.

09

### Attend the full programme

The 27 July briefing, overnight build, 10:00 p.m. WAT Day 2 submission, and Day 3 pitch availability are compulsory for selected entrants.

10

### Follow venue controls

Comply with the code of conduct, overnight-access rules, and published venue-safety instructions.

DAY 02 / FINAL HANDOFF

### Submission checklist

- Target user and financial-inclusion problem
- Working prototype with meaningful AI
- Evidence of meaningful BMONI sandbox integration
- GitHub repository accessible to reviewers
- Judge-accessible pitch deck
- Product video recording and working MVP link
- Architecture or data flow connecting AI and BMONI
- Models, APIs, datasets, tools, and pre-existing assets
- Privacy, security, and responsible-AI note

Final project submission closes at 10:00 p.m. WAT on 30 July. Late submissions will not be judged. Use the project submission form on this page.
